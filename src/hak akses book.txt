Easy Setup Permission & Menu Framework
Software Design Document (SDD)

Versi: 1.0 Draft
Framework: Laravel 12 + Livewire 4 + Spatie Permission

BAB 1
Pendahuluan
1.1 Latar Belakang

Sebagian besar starter kit Laravel menggunakan Spatie Permission untuk mengatur hak akses.

Namun proses implementasi masih cukup manual karena developer harus:

membuat permission satu per satu,
menghubungkan permission dengan route,
membuat sidebar secara manual,
mengatur menu terpisah dari permission.

Framework ini dibuat untuk menyederhanakan proses tersebut tanpa menghilangkan fleksibilitas Laravel.

1.2 Tujuan

Framework memiliki tujuan utama:

Easy Setup
Easy Maintain
Easy Extend
Mendukung Livewire maupun Controller
Tidak menggunakan Reflection
Tidak menggunakan PHP Attribute
Tidak melakukan scan Method
Permission berbasis Route Name
1.3 Target Pengguna

Framework ditujukan untuk:

Laravel Developer
Freelancer
Software House
Internal Company

Bukan ditujukan untuk End User.

📌 Catatan Arsitektur (Menurutku Penting)

Sebelum kita coding, ada satu keputusan desain yang menurutku perlu kita tetapkan di dokumen ini:

permission:sync harus bersifat idempotent. Artinya, dijalankan berkali-kali tidak membuat permission ganda, hanya menambah, memperbarui, atau menghapus (opsional dengan --clean) sesuai konfigurasi.
route:sync tidak boleh menghapus route yang hilang secara otomatis. Lebih aman memberi status seperti is_active = false atau menandainya sebagai tidak ditemukan agar programmer bisa meninjau perubahan. Ini mengurangi risiko kehilangan konfigurasi jika ada route yang sementara dihapus saat development.

Kalau dua aturan ini kita tetapkan sejak awal, implementasi nanti akan jauh lebih aman dan stabil. Menurutku setelah BAB 4 dan 5 ini, kita sudah siap masuk ke tahap coding dengan fondasi yang jelas.

FDR-009 — Authorization Source

Framework tidak akan menyimpan permission di tabel menus.

Permission selalu diambil dari system_routes.route_name.

Flow:

Menu
        │
        ▼
System Route
        │
        ▼
Route Name
        │
        ▼
convertPermission()
        │
        ▼
Permission
        │
        ▼
auth()->user()->can(...)

Jadi:

menus tetap hanya mengurus tampilan.
system_routes menjadi sumber identitas halaman.
PermissionSyncCommand tetap menjadi satu-satunya tempat yang mengubah route menjadi permission.

Aku sengaja memilih ini supaya tidak ada duplikasi data. Kalau suatu hari nama route berubah, cukup jalankan:

php artisan framework:route-sync
php artisan framework:permission-sync
